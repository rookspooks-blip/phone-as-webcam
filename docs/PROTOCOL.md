# Протокол Lensbridge — `lbp/1`

> Собственный протокол, не совместим с DroidCam/Iriun и не основан на них.
> Ключевые слова НУЖНО / СЛЕДУЕТ / МОЖНО — в смысле RFC 2119.
> Эталонная реализация: `desktop/crates/lb-proto` (Rust) и `mobile/ios/Lensbridge/Protocol` (Swift).

## 1. Роли

- **Сервер** — телефон. Снимает, кодирует, слушает порты.
- **Клиент** — ПК (`lensbridge`, `lb-sim` в тестах).
- **Часы сервера** — монотонные часы телефона, мкс (`u64`). На iOS — host time clock `CMClockGetHostTimeClock()`, в нём же метки и камеры, и микрофона. **pts** — момент захвата в этих часах.

## 2. Порты и транспорт

| Порт | Что | Защита |
|---|---|---|
| **4748/tcp** | Основной канал `lbp/1`: управление + видео + звук в одном TCP-соединении | Только после пейринга: общий ключ из QR, ChaCha20-Poly1305 |
| **4747/tcp** | HTTP: `/` (страница), `/video` (MJPEG), `/info` | Без шифрования. **Выключен по умолчанию**, включается в приложении. Принимает только loopback и приватные адреса |

USB (iOS): клиент подключается к порту 4748 устройства через usbmuxd (`Connect`), протокол тот же.

Обнаружение: Bonjour/mDNS `_lensbridge._tcp.local`, порт 4748, TXT-записи: `v=1`, `name=<имя устройства>`, `id=<16 hex — идентификатор установки приложения>`.

## 3. Пейринг (QR)

1. ПК генерирует 32-байтовый ключ `K` (CSPRNG) и хранит его (Windows — DPAPI-защищённый файл; macOS/Linux — файл с правами 0600).
2. ПК показывает QR со строкой:
   ```
   lensbridge://pair?v=1&k=<base64url(K) без '='>&n=<URL-encoded имя ПК>
   ```
3. Телефон сканирует QR и сохраняет `K` в Keychain под `key_id = SHA-256(K)[0..8]`. Телефон может хранить ключи нескольких ПК.
4. Сетевого обмена при пейринге нет. Входящие подключения на ПК не нужны, брандмауэр ПК не мешает.

Отзыв: удалить ПК в списке на телефоне или нажать «Новый ключ» на ПК (старый ключ на телефонах перестаёт подходить).

**Отличие от первоначального ТЗ (TLS + pinning).** iOS не даёт API для генерации X.509-сертификата, а rustls не поддерживает TLS с внешним PSK. Схема «общий ключ из QR + AEAD» даёт то же самое: взаимную аутентификацию, конфиденциальность, целостность и защиту от повторов. Реализуется стандартными примитивами (CryptoKit на iOS, RustCrypto на ПК).

## 4. Handshake (открытым текстом, фиксированный размер)

```
Клиент → сервер (28 байт):  "LBP1" | key_id[8] | nonce_c[16]
Сервер → клиент (21 байт):  "LBP1" | status u8 | nonce_s[16]
```

`status`: `0` — OK; `1` — неизвестный `key_id` (не сопряжён); `2` — занят (активна другая сессия); `3` — версия не поддерживается. При `status ≠ 0` сервер закрывает соединение (поле `nonce_s` — нули).

Ключи сессии (HKDF-SHA256, RFC 5869):
```
salt = nonce_c || nonce_s
k_c2s = HKDF(ikm=K, salt, info="lbp1 c2s", L=32)
k_s2c = HKDF(ikm=K, salt, info="lbp1 s2c", L=32)
```

Таймаут handshake — 5 с с каждой стороны.

## 5. Зашифрованные кадры

После handshake весь трафик идёт кадрами:

```
len u32 BE | ciphertext[len]          (len включает 16-байтовый тег Poly1305, len ≤ 8 MiB)
```

- AEAD: ChaCha20-Poly1305 (RFC 8439), ключ — `k_c2s` или `k_s2c` по направлению.
- Nonce (12 байт): `00 00 00 00 | counter u64 BE`, счётчик начинается с 0 и растёт на 1 на каждый кадр в своём направлении. Повтор/пропуск кадра = ошибка расшифровки = разрыв соединения.
- AAD — пусто.
- Открытый текст: `type u8 | payload`.

| `type` | payload |
|---|---|
| `0` CONTROL | JSON (UTF-8), §7 |
| `1` VIDEO | медиазаголовок + access unit H.264 (Annex B) |
| `2` AUDIO | медиазаголовок + PCM |

Первый кадр клиента НУЖНО отправить `hello` (§7.1). Успешная расшифровка `hello` подтверждает, что у клиента есть ключ `K`; успешная расшифровка `welcome` — что он есть у сервера.

## 6. Медиазаголовок (14 байт, BE)

```
codec u8 | flags u8 | seq u32 | pts_us u64 | данные…
```

| Поле | Значения |
|---|---|
| `codec` | `1` MJPEG (резерв), `2` H.264 Annex B, `16` PCM s16le, `17` AAC-ADTS (резерв) |
| `flags` | bit0 `KEY` (IDR), bit1 `CONFIG` (кадр содержит SPS/PPS), bit2 `DISCONT` (разрыв: смена формата/камеры, восстановление после прерывания) |
| `seq` | свой счётчик для видео и для звука |
| `pts_us` | pts первой выборки/кадра |

**Видео:** H.264, без B-кадров, каждый IDR предваряется SPS+PPS в том же кадре (`KEY|CONFIG`). Ключевой кадр — каждые 2 с и по `request_keyframe`. Если очередь отправки > ~150 мс, сервер выбрасывает кадры до следующего IDR, принудительно делает IDR и ставит `DISCONT`.

**Звук:** PCM s16le, 48 000 Гц, моно, порциями как отдаёт ОС (обычно 10–25 мс). Параметры дублируются в `stream_config`. Трафик ≈ 0,77 Мбит/с — нормально для LAN/USB.

## 7. Управляющие сообщения (JSON)

Общий вид: `{"t": "<тип>", "id": <u32, необязателен>, ...}`. Запросы с `id` получают ответ с тем же `id` (`ack`, `caps`, `pong` или `error`). Неизвестные поля НУЖНО игнорировать.

### 7.1 hello / welcome
```json
{"t":"hello","proto":1,"client":"lensbridge-desktop","version":"0.1.0","name":"MY-PC"}
{"t":"welcome","proto":1,"server":"lensbridge-ios","version":"0.1.0","device":"iPhone 13 Pro","server_time_us":812345000000,"state":{ /* как applied в ack */ }}
```

### 7.2 get_caps → caps
```json
{"t":"get_caps","id":1}
{"t":"caps","id":1,"cameras":[
  {"id":"com.apple.avfoundation.avcapturedevice.built-in_video:0","name":"Задняя широкоугольная","position":"back",
   "formats":[{"w":1920,"h":1080,"min_fps":1,"max_fps":60},{"w":1280,"h":720,"min_fps":1,"max_fps":120}],
   "zoom_min":1.0,"zoom_max":16.0,"torch":true,"focus_poi":true,"exposure_poi":true,
   "ev_min":-8.0,"ev_max":8.0}],
 "audio":{"rate":48000,"channels":1}}
```
Форматы перечисляются **динамически** из `AVCaptureDevice.formats` (дубликаты по размеру схлопываются, берётся максимальный FPS). Ничего не захардкожено.

### 7.3 set → ack
```json
{"t":"set","id":7,"p":{
  "camera":"<id>","w":1280,"h":720,"fps":30,"bitrate":6000000,
  "zoom":1.5,"torch":false,"mirror":false,
  "focus":{"x":0.5,"y":0.4},"focus_mode":"continuous",
  "exposure":{"x":0.5,"y":0.4},"ev":0.0,
  "audio":true,"screen":"dim"}}
{"t":"ack","id":7,"applied":{ /* фактическое состояние целиком */ }}
```
Все поля `p` необязательны. Сервер подбирает ближайшее поддерживаемое значение; в `applied` всегда фактическое состояние. Координаты фокуса/экспозиции — нормированные `0..1` в системе кадра, который видит клиент (левый верх = `0,0`), без учёта зеркалирования. `focus_mode`: `continuous` | `auto` (однократно по точке) | `locked`. `mirror` сервер только хранит; зеркалит клиент. `screen`: `on` | `dim`.

### 7.4 ping / pong (синхронизация часов)
```json
{"t":"ping","id":42,"c0":1700000000123456}
{"t":"pong","id":42,"c0":1700000000123456,"s1":812345678901}
```
Клиент шлёт раз в 1 с. При приёме в момент `c2`: `rtt = c2 − c0`, `offset = s1 − (c0 + c2)/2`. Используется оценка с минимальным `rtt` в скользящем окне 30 с.

### 7.5 Прочее
- `{"t":"request_keyframe"}` — немедленный IDR.
- `{"t":"bye"}` — корректное завершение.
- Сервер → клиент:
  - `stream_config`: `{"t":"stream_config","video":{"codec":"h264","w":1280,"h":720,"fps":30},"audio":{"codec":"pcm_s16le","rate":48000,"channels":1}}` — после `welcome` и при каждом изменении;
  - `stats` (раз в 1 с): `{"t":"stats","fps":29.9,"kbps":5800,"dropped":0,"battery":0.81,"charging":true,"thermal":"nominal"}`;
  - `event`: `{"t":"event","kind":"interrupted|resumed|orientation|thermal","detail":"..."}`;
  - `error`: `{"t":"error","id":7,"code":"bad_request|unsupported|camera_unavailable|internal","message":"..."}`.

## 8. Тайминги

| Параметр | Значение |
|---|---|
| Handshake | 5 с |
| Keepalive | клиентский `ping` раз в 1 с; нет входящих данных 5 с → соединение мёртвое |
| Переподключение клиента | 0,5 → 1 → 2 → 4 → 5 с (максимум), сброс после 10 с стабильной работы |
| Восстановление камеры | после прерывания (звонок, сворачивание) — автоматически при `InterruptionEnded`/возврате приложения, затем `DISCONT` + IDR + `event resumed` |
| Сессии | одна активная. Новый клиент получает `status=2`, пока старая жива; мёртвая сессия освобождается по keepalive |

## 9. HTTP-порт 4747 (по умолчанию выключен)

- `GET /` — HTML-страница с `<img src="/video">`.
- `GET /video` — `multipart/x-mixed-replace; boundary=lbframe`, части `image/jpeg` с заголовками `X-LB-Seq` и `X-LB-PTS`. До 3 зрителей; медленному зрителю кадры пропускаются.
- `GET /info` — `{"proto":1,"device":"…","name":"…"}`.

## 10. Версии

`proto` в `hello`/`welcome` и `"LBP1"` в handshake. Несовместимые изменения → `LBP2`. Совместимые дополнения — новые необязательные поля JSON и новые значения `codec`/`type` (неизвестный `type` кадра НУЖНО игнорировать).
